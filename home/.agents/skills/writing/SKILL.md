name: writing
description: Style guide for written technical communication. Use this skill when writing or editing pull request descriptions, commit messages, issue descriptions, release notes, README content, documentation prose, or any written summary of technical work.
---

When writing descriptions of work for use in pull request descriptions, issue
descriptions, release notes, or documentation, or other writing intesnive tasks follow these guidelines:

- Do not use emdashes.
- Write in a professional technical tone.
- Do not use emojis.
- Do not overuse bullet lists. They can be helpful but are easily overused;
  prefer prose when the content flows naturally as paragraphs.
- Focus on the **why** of the work, not the **how**. The code speaks to the how.
- Be concise. Avoid filler phrases, handwavey jargon, and unnecessary qualifiers.
- Eliminate statements that are imprecise and unqalified, and only exist to make something "sound" smart.
